# FB-007 — println 长度口径不一致：字面段用原始跨度、字符串实参用转义后长度

- **反馈环批次**：第二批（lowering/text 线 (c) 类）
- **源登记**：`docs/divergences/lowering-text.md` D-T6；合编 `docs/DIVERGENCES.md`
- **分类**：Zig 侧缺陷候选 —— 源码机制定案（口径不一致）
- **Rust 侧处置**：逐字镜像两条口径（`crates/sla-codegen-text` println.rs），候主线裁决。

## 机制（Zig 源码位置）

- `src/codegen.zig` 约 2185：格式串**字面段**的长度以原始源码
  跨度 `i - start` 计算（转义序列按多字节计）。
- `src/codegen.zig` 约 2195：**字符串实参**的长度以
  `escapedStringByteLen`（转义后的实际字节数）计算。

## 影响

- 同一常量在两条路径下长度口径不同：当格式串的字面段内含
  转义序列（如 `\n`、`\t`）时，段路径按原始字节数打印，
  会把转义文本的**原始拼写多打出来**（输出含字面反斜杠等
  多余字节），实参路径则正确。输出错误且静默。

## 建议修复形态（仅建议，不预判主线最终形态）

两条路径统一到转义后的实际字节长（与实参路径一致），或
统一在发射前对段文本做一次转义求值再取长度。修复后差分
复核以「格式串段含转义序列」的 println 为最小输入。

## Rust 侧锚点

`crates/sla-codegen-text` println.rs 两条口径均逐字镜像并
注源行号；主线统一口径后 Rust 侧同步，含转义段的 fixture
应作专项对拍件补入对拍集。
